# 合规度评分

> 折入自 `medical-device-compliance-grader`（2026-10-27 聚合）：把「医疗器械合规程度」量化成**可比较的分数**——注册前自评、发补整改验证、多产品横向对比，一个工具三个用途。配合 `scripts/grade_compliance.py` 一键生成自包含 HTML 评分卡（雷达图 + 明细表 + 改进建议，纯 SVG 无外部依赖）。

## 8 大维度 × 0–5 分（评分锚点统一）

| 分值 | 含义 | 判定标准 |
|---|---|---|
| 0 | 缺失 | 完全无相关文件/活动 |
| 1 | 仅提及 | 只有口头/纪要提及，无成文文件 |
| 2 | 部分成文 | 有部分文件，但结构不完整/未覆盖全部要求 |
| 3 | 基本完整 | 文件齐全、结构符合要求，可支撑注册/审评 |
| 4 | 完整可查证 | 文件完整且互相引用闭环，证据可追溯 |
| 5 | 标杆级 | 完整 + 经审评/审核认可或按最佳实践持续维护 |

> 评分基于**现有证据**（文件路径/状态），证据缺失即低分。

| 维度 | 考察点 | 法规依据 |
|---|---|---|
| **D1 注册路径与分类** | 分类界定（中 I/II/III、美 Class I/II/III、欧 Rule 分类）、注册路径（备案/注册/510(k)/De Novo/PMA/CE）、分类依据文件 | NMPA 分类目录、《医疗器械分类规则》、FDA 21 CFR、MDR Annex VIII |
| **D2 技术文件完整性** | 技术文档结构按目标市场组织（STED 六章 / MDR Annex II / 121 号模块）、描述/设计制造/验证齐全 | IMDRF STED、MDR Annex II/III、2021 年第 121/122 号公告 |
| **D3 风险管理** | 风险管理报告（ISO 14971 六步）、危害识别、风险矩阵与可接受准则、控制措施验证、残余风险结论 | ISO 14971:2019 / GB/T 42062-2022、MDR Annex I GSPR、21 CFR 820.30 |
| **D4 临床评价** | 路径判定（免临床/同品种/试验）、CER 结构（等同性论证、文献检索方案）、获益-风险结论 | 免临床目录（2025 年版）、MDCG 2020-13、FDA 510(k) SE |
| **D5 标签与说明书** | 标签要素（UDI、灭菌信息、符号）、IFU 内容（含再处理）、语言符号合规、版本管理 | 局令 6 号、MDR Annex I 23 条、MDCG 2019-15、21 CFR 801/809、ISO 15223-1:2021 |
| **D6 软件与网络安全**（如适用） | SaMD/嵌入式判定、风险分类（IMDRF N12 / 三级关注 / MDR 规则 11）、IEC 62304 文档、网络安全（威胁建模/SBOM/漏洞）、人因 | IEC 62304、IMDRF N12、MDCG 2019-16、FDA 软件/网络安全指南、CMDE 软件注册指导原则 |
| **D7 上市后监管** | PMS 计划、不良事件监测报告（渠道/时限）、定期报告（PSUR/PMS Report）、FSCA/召回流程、PMCF | 21 CFR 803、MDR 87–92 条 + MDCG 2022-21、中国 2018 年第 1 号令 |
| **D8 质量体系** | 体系文件（ISO 13485/中国 GMP）、设计控制（DHF）、供应商管理、CAPA、内审管理评审、体系核查状态 | ISO 13485:2016、中国 GMP 规范、21 CFR 820（QMSR） |

> 注：纯无源器械 D6 评 **N/A**（不计入总分分母），但人因（IFU 可用性）仍应在 D5/D3 体现。

## 总分与等级

| 等级 | 总分（含 N/A 折算） | 判定 |
|---|---|---|
| A（优） | 4.0–5.0 | 可支撑申报/持续合规，短板已可控 |
| B（良） | 3.0–3.9 | 基本可申报，存在待补项（建议整改后申报） |
| C（中） | 2.0–2.9 | 缺项较多，须系统补全后再申报 |
| D（差） | 0.0–1.9 | 证据严重不足，先建体系再谈申报 |

总分算法：适用维度平均分（N/A 维度不计入分母），脚本自动计算。

## 改进建议（脚本按短板自动生成）

| 维度 ≤ 2 分 | 建议 |
|---|---|
| D1 | 先做分类界定/路径判定（官方分类目录或分类界定申请），明确产品类别再启动后续 |
| D2 | 以 STED 六章搭骨架，按目标市场官方模板补全章节 |
| D3 | 立即补风险管理报告（ISO 14971 六步流程），与验证/临床文件互相引用 |
| D4 | 先做路径判定（免临床/同品种/试验），再按官方模板写 CER |
| D5 | 按标签要素检查表 + IFU 框架逐项补全，符号用 ISO 15223-1 |
| D6 | 先判定软件身份与风险分类，再按 IEC 62304 搭文档 + 网络安全评估 |
| D7 | 建 PMS 计划 + 不良事件监测报告流程，明确各市场报告时限 |
| D8 | 建/完善质量体系文件与设计控制记录，安排内审与整改 |

## 评分输入 JSON 格式（脚本输入）

```json
{
  "product": "关节镜用复用外科器械",
  "market": "中国 II 类 / 欧盟 MDR IIa / 美国 510(k)",
  "date": "2026-08-27",
  "scores": {
    "D1": {"score": 4, "note": "分类已按目录确认 II 类，路径已定"},
    "D2": {"score": 3, "note": "STED 骨架已搭，验证章节待补"},
    "D3": {"score": 2, "note": "风险管理报告初稿，缺控制措施验证记录"},
    "D4": {"score": 1, "note": "尚未启动临床评价路径判定"},
    "D5": {"score": 3, "note": "标签草稿已有，缺 UDI 与符号核验"},
    "D6": {"score": "N/A", "note": "纯无源器械，无软件"},
    "D7": {"score": 2, "note": "PMS 计划未建，不良事件渠道已接入"},
    "D8": {"score": 3, "note": "ISO 13485 体系运行中，DHF 待完善"}
  }
}
```

- `score` 取 0–5 整数或 `"N/A"`（不计入分母）；`note` 为证据备注，供报告与复评对比。

## 脚本用法

```bash
# 生成示例评分卡（了解输出）
python scripts/grade_compliance.py --demo

# 用你的评分文件生成报告（JSON 格式见上）
python scripts/grade_compliance.py --input scores.json --out report.html

# 同时输出 JSON 结果（供留档/复评对比）
python scripts/grade_compliance.py --input scores.json --out report.html --json scores_result.json
```

## 使用示例

- **注册前自评**：按 8 维收集证据打分 → 跑脚本 → 雷达图显示临床评价是短板 → 报告建议优先补 CER/同品种论证 → 按建议排整改计划。
- **发补整改验证**：整改前评 2 分、整改后复评 4 分 → 两次评分卡对比，证明整改闭环。
- **多产品对比**：同维度分数横向比较 → 资源优先投分数最低的产品。

## 使用边界

- 自评工具：结论仅代表按维度锚点的自评状态，**不构成**监管机构/公告机构的正式裁定，不替代专业 RA 审查。
- 维度覆盖主流合规要求，创新器械/AI 软件/特殊材料可能需按产品特性增补维度；评分基于提供的证据，证据缺失即低分。
